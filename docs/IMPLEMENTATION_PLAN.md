# 开发总规划

## 目标与边界

交付一套电脑端优先、支持 2–4 名朋友通过游戏码联机的隐藏手牌推理卡牌游戏。服务端是唯一真实状态来源；产品不包含账号系统、陌生人匹配、公共大厅、观战、原生 App 或商业化能力。

原版规则和私有美术内容分开处理：规则只能依据用户提供的规则书或卡牌资料实现；原牌名、逐字说明、角色、插画、图标和 Logo 由部署者放入仓库外的私有内容包。

## 技术方案

- 前端：Vue 3 + TypeScript，桌面浏览器优先。
- 联机入口：Cloudflare Worker，提供房间 HTTP API 和 WebSocket。
- 房间状态：每个房间对应一个 SQLite-backed Durable Object，串行裁决命令。
- 游戏核心：无界面的 TypeScript 纯逻辑包，负责房间状态、隐藏信息投影和规则接口。
- 协议：独立的运行时命令解析包，拒绝格式错误或未知命令。
- 部署：静态前端和 Worker 一起发布到免费的 `workers.dev` HTTPS 地址。

## 阶段与验收

### 第一阶段：可联机骨架（已完成）

- 创建私人房间并获得 6 位游戏码。
- 2–4 人通过昵称和游戏码加入，无需注册。
- 全员准备后由房主开局；开局后拒绝新玩家。
- 服务器发牌，并针对每个连接生成不同视图：自己的牌面隐藏、他人的牌面可见。
- 活跃对局断线后立即暂停，原匿名身份在 90 秒内可恢复。
- 等待房间离开与房主转让、对局认输与仅剩玩家获胜。
- 命令去重、错误协议、Durable Object 持久化和个性化 WebSocket 广播。
- 八种牌的效果注册接口，不内置未经确认的原版效果。

本阶段的可玩边界是“建房—加入—准备—开局—验证隐藏视图—断线/退出”；尚不能通过施法完整结束一局。

### 第二阶段：原版规则闭环（已完成）

输入条件：用户上传规则书，以及八种牌可辨认的照片或 PDF。

- 已根据用户提供的正文建立公共设置、回合与计分规格，并逐条标注缺口。
- 已实现起始手牌、秘密咒语、人数差异、声明/验证、连续声明限制、轮次计分和整局胜负。
- 已依据用户提供的规则页实现八种牌的伤害、治疗、骰值、邻座目标和猫头鹰秘密选择。
- 已接入正式牌库数量、6 点起始生命、`1,1,1,2,2,3` 骰面分布和按编号落牌图板。
- 已确认并实现两人局闪电累计 2 点伤害、逐轮轮换先发和同时达到 8 分并列获胜。
- 已按补充规则实现每轮空图板、秘密咒语不可施放，以及玩家回合结束后补普通手牌到 5 枚。
- 为每种牌先写规则测试，再接入效果注册器。
- 增加施法、目标选择、猜测自己手牌、结算、淘汰和完整结束流程。
- 覆盖 2、3、4 人局，以及断线、认输和边界组合。

验收标准：不依赖客户端信任，完整牌局能从开局进行到唯一胜者，关键规则样例均有自动化测试。

### 第三阶段：私有内容与桌面体验（功能已完成，等待正式素材）

- 已定义私有内容包格式和缺失素材回退方式。
- 已接入角色选择、名称、说明、图板、角色图和牌图替换接口。
- 已完善桌面牌桌、目标提示、操作确认、公开对局记录和计分结算；动画与音效按用户要求不作为首版必需项。
- 已覆盖刷新、重复连接、错误游戏码和断线恢复；公网慢网体验留到正式地址实测。

验收标准：未安装内容包时仍能以通用素材运行；安装内容包不会改变服务端规则。

### 第四阶段：上线与朋友实测

- 在部署者 Cloudflare 账号创建正式 Worker，并取得 `workers.dev` 地址。
- 用不同网络、不同浏览器进行 2–4 人公网实测。
- 记录规则差异、网络问题和易用性问题，按严重程度修正。
- 固化部署、回滚和备份说明。
